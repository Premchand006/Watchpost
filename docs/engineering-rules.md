# Engineering rules

Rules and conventions for changing Watchpost. Requirements are in `docs/prd.md`, milestones and status in
`docs/build-plan.md`, Pi setup in `docs/hardware-setup.md`.

## What this is

Person detection and tracking in three tiers:

1. Edge (`edge/`): the Python package `watchpost` on a Raspberry Pi 5. Reads up to three cameras
   (USB via `v4l2`, CSI via `picamera2`), runs YOLO26 detection and ByteTrack tracking, evaluates
   zones, checks camera health, picks best-frame crops, and publishes events, people, camera rows,
   telemetry and images to Supabase. All heavy AI runs here.
2. Cloud (`cloud/`): Supabase (Postgres, Auth, Realtime, Storage). No custom backend server.
3. Web (`dashboard/`): React, Vite and Tailwind, deployed to Vercel or Netlify, talking to Supabase
   through `@supabase/supabase-js`.

The dashboard is hosted publicly and cannot reach the Pi on the LAN. The Pi pushes up to Supabase;
the dashboard reads down from Supabase. Never write code that assumes the browser connects to the
Pi.

## Golden rules

1. Never run YOLO on every frame of every camera. The path is: motion gate, then strided and
   staggered YOLO, with ByteTrack keeping identities across the gaps. This is why the Pi copes.
2. The Supabase service key lives only on the Pi (`edge/.env`). The dashboard uses the anon key
   only. Never put the service key in `dashboard/`. Never commit either `.env` or
   `dashboard/.env.local`.
3. Networking never blocks the vision loop. Publishing happens on a background thread with local
   buffering (SQLite plus a disk spool) on failure.
4. RBAC is enforced by RLS, column grants and triggers in Postgres, not by hiding buttons. UI gating
   is convenience only.
5. Raw video stays on the Pi. Only structured rows, best-frame crops and small annotated snapshots
   go to the cloud. Both buckets are private and read through signed URLs.

## Layout and commands

```text
edge/
  watchpost/        __main__ (CLI) · engine (orchestration only) · cameras · motion · detector
                    tracker · zones · bestframe · health · snapshot · telemetry · publisher
                    sinks · config · events · runtime
  tools/camera_test.py
  tests/            pytest with fake cameras, clock and sink
  deploy/           install.sh, watchpost.service
  config.yaml, .env.example, pyproject.toml, requirements.txt
cloud/
  schema.sql        full schema for a new project
  migrations/       001_initial.sql (v1), 002_watchpost.sql (upgrade v1)
  seed.sql          optional demo rows
  tests/rls_checks.sql   run in the SQL editor; must end with "rls_checks: all passed"
dashboard/          see dashboard/README.md
docs/               prd, build-plan, hardware-setup, demo-script, upgrading, design/, images/
```

```bash
cd edge && python -m watchpost [--config config.yaml] [--dry-run] [--show]
python edge/tools/camera_test.py [--save]
python -m pytest edge/tests -q && ruff check edge
cd dashboard && npm run lint && npm test -- --run && npm run build
```

Keep `cloud/schema.sql` and the latest migration in step. A schema change needs a new numbered
migration for existing projects, and a matching check in `cloud/tests/rls_checks.sql` if it touches
access rules.

## Detector: YOLO26

- Package `ultralytics` (`yolo26n` ships in it).
- Usage:
  ```python
  from ultralytics import YOLO
  model = YOLO("yolo26n.pt")
  model.export(format="ncnn")            # creates yolo26n_ncnn_model/
  ncnn_model = YOLO("yolo26n_ncnn_model")
  results = ncnn_model(frame)            # NMS-free, end-to-end
  ```
- Always run NCNN on the Pi. The model folder is generated by `edge/deploy/install.sh` and is
  gitignored.
- YOLO26 is NMS-free. Do not add an NMS step.
- Export can fail with `Illegal instruction (core dumped)` on a Pi 4 (16K vs 4K page size). It works
  on a Pi 5. Otherwise export on a laptop or in `ultralytics/ultralytics:latest-arm64` and copy the
  folder.
- Fallback: `yolo11n.pt` or `yolov8n.pt` with the same API. Ask before switching and note it in a
  code comment.

## Tracking

ByteTrack via `supervision` (`sv.ByteTrack`), one tracker per camera, updated only on YOLO ticks
(`edge/watchpost/tracker.py`). `supervision` is pinned below 0.31 because 0.31 removed
`sv.ByteTrack` (it moved to Roboflow's `trackers` package, which `tracker.py` also accepts).

## Conventions

- Python 3.10 or newer (Raspberry Pi OS Bookworm ships 3.11). Type hints, `ruff`-clean (config in
  `edge/pyproject.toml`), no global mutable state. Config from `edge/config.yaml`, secrets from
  `edge/.env` via `python-dotenv`. Use `logging`, not `print` (the `tools/` scripts may print).
- Keep `engine.py` orchestration only; put logic in the modules. Split a file when it passes about
  250 lines.
- picamera2 comes from apt (`python3-picamera2`), so the venv is made with
  `--system-site-packages`. Import it lazily so tests and non-Pi machines work without it.
- Frontend: function components and hooks, Tailwind for layout, one client in
  `src/lib/supabase.js`, data hooks in `src/hooks/` shared through `src/context/DataContext.jsx`.
  No Redux. Keep the visual language of `docs/design/dashboard-mockup.jsx` (dark, semantic accent
  colours, monospace telemetry). No `localStorage` or `sessionStorage` for app state; use Supabase
  and React state.
- Web env vars: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (optional `VITE_NODE_ID`). Set them in
  the Vercel or Netlify project settings, never hardcode.
- Commits: small, one milestone or fix each, conventional prefixes (`feat:`, `fix:`, `chore:`,
  `docs:`).

## Definition of done

- Edge tests and ruff pass, dashboard lint, tests and build pass.
- Runs on the actual Pi or deploys to Vercel, not just compiles.
- Respects the golden rules.
- The PR description has a one-line manual test ("walk in front of CAM-02, an `enter` event
  appears").
- No secrets committed.

## When unsure

- Prefer the simplest thing that demos. V1 first (`docs/prd.md` section 2), V2 only after V1 passes
  its success metrics.
- If a hardware or library detail is uncertain (driver quirks, FPS, export behaviour), say so and
  propose a test instead of guessing.
